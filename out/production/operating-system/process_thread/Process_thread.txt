1. Process:
- It's a program that is running in the memory and has its own isolated address space.
2. Thread:
- It's a part of a process, and if multiple threads are running in the same process,
they share the same address space.

=> - Thread and process execution depend heavily on the CPU and the OS. which handles context switching.
- without initializing a thread pool, an explosion of incoming req with creat too many threads
this forces CPU to constantly switch context, leading to high overhead(CPU thrashing)
and maybe even slowing down the system.
- CS of a thread is faster and cheaper than process. cuz CS of a thread is the same memory space.(except diff process)

3. Multithread:
- Concurrency: interleaved thread
- Parallelism: 2 or more thread running at the same time.

4.Virtual thread:
- why does VT appear?
=> before, computer used thread platform. each thread is expensive and
heavily, and it spend 1-2MB ra(for stack). So server can handle maximum a few thousand threads.
and when calc is heavy, more threads -> more CS -> performance drops
- VT is a way to reduce the cost of thread. And VT multiplex many VT onto few carrier(physical) threads.
when VT blocks on I/O, JVM unmounts it from carrier - carrier runs another VT. So we can write code in sync style and JVM handles
the multiplexing behind the scences(java 21+)
and VT handle process async and now we can write code in sync way and VT will be process async behind the scene.(java 21)
- VT is managed by Application. Different from physical thread which is managed by OS.
- trade-off VT vs thread:
+ I/O bound: VT wins - millions of VTs, carrier never idles
+ CPU-bound: VT never unmounts → sticks to carrier the whole time → behaves exactly like platform thread.
 Even worse — platform thread has OS time quantum (forced turn-taking), VT does not → other VTs starve

5. Multithreading
- life cycle multi thread: new - runnable - running - blocked/waiting - terminated
                                               ↑_____________|
- Concurrency problem:
+ race condition: 2 threads read/write shared data simultaneously -> data is inconsistent
+ deadlock: 2 threads are waiting for each other -> deadlock
+ starvation: based on priority low thread -> thread with high priority is always executed and low priority will never be executed.
+ mutex: binary lock(1 or 0). Only 1 thread holds it at a time. (Synchronization tool)
+ semaphore: counter-based sync. (Synchronization tool)

- Keywords in Java:
+ synchronized: lock OS-level, thread sleeps, low performance. When to use a complexity-critical section.
+ Atomic: fast, only compute add/minus/compare number.
+ volatile: only 1 thread write and threads read.
